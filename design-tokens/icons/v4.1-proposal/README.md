# Plantim Icons v4.1 — proposal

Additive proposal on top of the shipped v4 set: **27 semantic icons** (loading
states & placeholders, specific app cases) and a **14-flag `flag.*` asset
class**. Nothing here changes an existing id; the shipped `v4/` registry,
packages and hashes are untouched.

Review package (regenerated by `npm run icons:proposal:html` / `icons:proposal:pdf`):

| artifact | purpose |
| --- | --- |
| `reports/plantim-icons-v4.1-proposal-catalog.html` | interactive catalog + decision record (Approve / Improve / Redraw / Reject, notes, .md/.json export) |
| `reports/plantim-icons-v4.1-proposal-catalog.pdf` | print catalog: every variant, 16→48 ramp, rationale, surfaces |
| `reports/plantim-icons-v4.1-proposal-report.pdf` | process report: why, method, gates, flag asset-class decision, a11y, delivery, promotion checklist, open decisions |

## Layout

```
v4.1-proposal/
  README.md                 this file
  rationale.mjs             per-id "why / where" + group definitions (single source for all reports)
  locales.proposal.json     a11y labels (en/de/tr) for new status/semantic ids and flags
  src/<group>.mjs           hand-authored icons in the v4 DSL (icon / layer / P / C / R)
  flags/src/flags.mjs       hand-authored flags in the flag DSL (flag / flagLayer / hStripes / …)
  registry.proposal.json    compiled, self-hashed (generated)
  index.proposal.json       manifest for catalogs/sheets (generated)
  svg/<variant>/<id>@<size>.svg   generated: 4 × 6 per icon, 2 × 6 per flag
```

## Commands

```sh
npm run icons:proposal          # generate + structural gate
npm run icons:proposal:raster   # + flood-fill counters / silhouette IoU (needs Playwright Chromium)
npm run icons:proposal:sheets   # contact sheets → reports/v4-sheets/proposal/ (gitignored)
npm run icons:proposal:html     # interactive catalog
npm run icons:proposal:pdf      # report + catalog PDFs
```

`PLANTIM_CHROMIUM=/path/to/chrome` lets the raster gate, sheets and PDFs use a
pre-installed Chromium instead of the Playwright download.

## Rules (enforced by `check-proposal-icons.mjs`)

- Ids must be **new** across v2, v3 and v4; verdict is always `new`; tiers are
  P1/P2 (P0 is reserved for shipped tab identities).
- Semantic icons obey every v4 structural rule (bounds, 3-decimal clamp, grade
  strokes, 4 × 6 size set, declared counters, token refs) and the raster gate.
- Status/semantic ids and all flags need a label in **every** locale
  (`locales/*.json` or `locales.proposal.json`).
- Flags: `color` variant has the clip + hairline border and no `currentColor`;
  colors are uppercase 6-digit hex; at least one layer survives micro.
- The proposal is pinned to the current `v4Hash`; it must be regenerated after
  any v4 change.

## Promotion

1. Export the decision record from the HTML catalog.
2. Move each approved `icon()` into `design-tokens/icons/v4/src/`, add it to
   `tiers.json`, merge its label keys into `locales/*.json`.
3. Flags: land `flags/src/flags.mjs` with the flag DSL/renderer as a generator
   input and add the web (`@plantim/icons/flags`), iOS and Android flag
   generators (see the report, "Platform delivery").
4. Bump the registry to 4.1.0, `npm run icons:v4` + raster + package + swift +
   android, then `npm run icons:validate`.
5. Delete promoted modules here so the proposal stays a delta.
